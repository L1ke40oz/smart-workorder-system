### 实际操作与开发顺序

1. 阅读用户指定 REFERENCES.md，查看四个仓库的 README 和目录；同时核对 Spring Boot、Android 组件、Gemini、硅基流动与 Lucene 的官方资料。参考关系及取舍已写入架构文档。
2. 创建 `backend/`：Java 17、Spring Boot 3.5.16、JPA、Flyway、Spring Security、JWT、Jakarta Validation，配置 Maven 构建。
3. 先实现基础业务：普通用户注册、登录、管理员初始化、权限隔离、文字工单、详情、搜索和筛选、接单、填写结果、完成和统计。
4. 实现并发保护：账号行锁与提交标识防止重复工单，工单行锁控制接单与状态变化，增加非法输入和冲突处理。
5. Android 接入 Java / XML / MVVM / ViewModel / LiveData / Retrofit / RecyclerView / ViewBinding，建立六个主要页面和返回导航。
6. 使用深绿、浅灰与卡片布局实现临时命名为“知序工单”的中文界面；完成角色首页、加载、失败、空列表、分页和确认交互，没有使用 emoji 装饰。
7. 使用 Android Keystore AES-GCM 加密保存 JWT；退出账号清除数据；Release 禁止明文 HTTP，Debug 提供本地连接设置。
8. 基础流程先通过后端测试和模拟器验收，再实现 Gemini 结构化分析。分析结果暂存、绑定用户与原文，30 分钟过期；用户确认后正式创建，允许修正结构化字段或明确改为手动填写。
9. 实现 Gemini 原生 REST、固定 Schema 和严格字段校验，处理未配置、限流、错误响应、无效 JSON、类型错误及截断结果。
10. 实现硅基流动 `BAAI/bge-m3` embedding 适配和 Lucene 9.12.3 HNSW 文件索引：完成后异步入库、指纹去重、每分钟分批补偿、手动请求同步、Top-3 检索、案例来源、余弦匹配度及受限编号引用。
11. RAG 无匹配不编造建议，建议生成失败保留检索案例；任何智能结果均不自动改变工单状态或填写实际处理结果。
12. 新增本地供应商 HTTP 测试接口，执行真实后端请求、数据库事务和 Lucene 检索；未使用真实模型密钥。
13. 创建独立临时 MySQL 8.0.45 实例，在 127.0.0.1:13306 上验证 Flyway、JPA 和 REST；未修改系统 MySQL80 服务。Android 连接该 MySQL 后端再次通过完整流程。
14. 新增可重复的 API 验收脚本，整理实际流程截图、运行说明、架构图、ER 图、状态机与智能模块时序图。
15. 增加项目协作约定 `AGENTS.md`，明确技术栈、文档维护、原文保留、角色与人工确认等要求。
